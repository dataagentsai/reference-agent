## Existing tags I believe are wrong (kept, not removed)

1. **test_cassette.py::test_a_changed_request_is_a_mismatch_not_a_silent_pass → AAC-0016.** AAC-0016 is a *scheduled re-run against unchanged inputs* that catches *provider-side* drift. A replay can never see provider drift. This test catches a change on *our* side. The nearest honest tag is AHC-0022, or an AgentTwin replay statement. The test does not discharge AAC-0016.
2. **test_cassette.py::test_a_whole_run_replays_from_disk_with_no_network → AAC-0010.** AAC-0010 means running the same input N times and measuring the spread (the noise floor). A replay has zero variance by construction and measures nothing about the model. The tag probably comes from the catalog's AHC-0022 → AAC-0010 mapping, but this test's assertions do not verify it. AAC-0059 on the same test is right.
3. **test_telemetry.py::test_span_carries_the_attributes_a_verdict_needs → AAC-0011.** The test sets the attributes itself and reads them back. It verifies the span helper, not that *every model call* emits a complete trace. The real AAC-0011 check is the suite-wide `_spans_conform_to_the_contract` autouse fixture in conftest.py, which no marker can tag. Weak, and arguably `tooling`.
4. **test_telemetry.py::test_trajectory_is_reconstructable_from_the_trace → AAC-0060.** The test emits `agent.step` and `agent.tool` spans by hand. It proves the trace-assertion mechanism (M5) works, not that the agent loop's trajectory can be rebuilt from its trace. It should be `tooling`, and AAC-0060 needs a test that drives `loop.run`.
5. Minor: **test_telemetry.py::test_redaction_replaces_sensitive_spans → AAC-0006.** AAC-0006 is about scanning *outputs*. This is a unit test of the telemetry `redact()` function, which fits AAC-0095 better. Tolerable.
6. Not my file: the `conftest.py` fixture docstring says "AHC-0011's 'complete trace'". It means AAC-0011.
