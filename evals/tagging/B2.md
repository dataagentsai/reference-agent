## Existing tags I believe are wrong or weak (kept, not removed)

1. **`test_policy.py::test_an_invented_entity_is_blocked`, AAC-0110. Likely wrong.** The test grounds
   entities (an order id, a date, a figure) against tool output. AAC-0110 says it is "distinct from
   faithfulness to retrieved content" and covers claims about the system's own actions. AAC-0029
   (already present) is the right tag. I did not add AAC-0110 there.
2. **`test_typed_boundary.py::test_the_failures_are_counted_not_merely_survived`, AAC-0099. Weak.**
   The test counts parse failures on the trace. AAC-0099 is "the output contract holds on every
   route", and no second route is exercised. AHC-0001 (added) fits better.
3. **`test_policy.py::test_a_refund_may_only_be_claimed_if_one_happened` and
   `test_a_false_claim_never_reaches_the_customer`, AAC-0003. Weak.** AAC-0003 is system-prompt
   constraint adherence, measured with M3. These tests check a deterministic runtime guardrail.
   AAC-0110 (added) is the precise fit.
4. **`test_approvals.py::test_a_large_refund_cannot_be_issued_before_it_is_granted`, AAC-0056.
   Weak.** It asserts only that `issue_refund` is missing from the customer's tool list. That is a
   view check, and nothing provokes the path. AHC-0040 says the view is not the authorisation.

## Caveats on tags I added

- **AHC-0094** on `test_a_false_claim_never_reaches_the_customer`. The test asserts
  `termination is REFUSED`, which matches AHC-0094. But the loop returns
  `Completed(reply=SAFE_REPLY, termination=REFUSED)`, not the `Refused` outcome type.
  AHC-0094/AHC-0017 call a substitute returned as an ordinary result "the system lying about its own
  behaviour". The tag covers the termination facet. The outcome-type facet is an implementation gap.
- **AHC-0018** on two trace tests. Only block and error decisions are recorded. Allow decisions and
  policy version are not recorded (and not implemented), so AHC-0018's allow half has no coverage.
- **P-REFUND / request_refund.** The threshold is applied to the `amount` argument the model supplies.
  The AOAS says `amount_from: order.total  # never from the conversation`. The boundary tests verify
  the ₹10,000 number, not where the amount comes from. That divergence is untested and looks like a
  real defect.

## Spec observations raised while tagging

- `policies.approval` (approver is never the customer, `valid_for: 24h`, `while_waiting`) carries no
  statement id, so the most-tested approval rules can only be tagged through the generic AHC-0057.
- `policies.personal_data_in_conversation` (card numbers) has no id. The card-echo case can only be
  tagged AAC-0006.
- `purpose.deferred` ("performs nothing, and claims nothing") has no id. The `dispatch_replacement`
  claim case can only be tagged AAC-0110.
- The AOAS marks `cancel_order` irreversible with `authority: agent`, while AHC-0057 (A6) requires an
  approval for every irreversible action. The two specs disagree.

## The 5 most important untagged behaviours

1. **Order-status claims are unchecked at runtime.** The agent can tell a customer "your order is
   delivered" when it has shipped. Only the AgentTwin truth oracle catches it (test_truth.py, all
   tooling). Missing AOAS statement: *The agent must never state an order status other than the one
   the order system returned in the same exchange.*
2. **Approval decisions are final** (`test_a_decision_is_terminal`). This is what stops one grant
   producing two refunds, and it has no statement.
3. **Approvals leave no trace record** (`test_the_decision_is_on_the_trace`). No AHC capability asks
   for approval requests and decisions to be recorded against the unit of work.
4. **The reviewer queue shows only undecided items** (`test_the_queue_shows_only_undecided_items`).
   `ext:approval_queue` describes latency but not what reviewers must see.
5. **The limits of runtime grounding** (`test_what_entity_grounding_cannot_catch`). Negation,
   entity-free inventions and miscounts pass. No statement requires them to be caught. Closely
   related is `test_the_failure_carries_the_raw_text_for_the_operator`: AHC-0001's `raw_retention`
   decision is unresolved, so that behaviour has no statement either.
