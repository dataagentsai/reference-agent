## Ids deliberately not added (precision)

- **Q-STEPS / Q-COST / Q-OUTPUT / Q-TOOL-RESULT**: no test in this batch asserts 12 steps,
  USD 0.50, 4096 tokens or 8000 characters. The budget tests override the values (4 steps,
  a 0.60 or 0.01 ceiling). The defaults sit in `config.Budgets` and nothing here checks them.
- **Q-TOOL-RESULT is also a probable code defect.** `MCPToolClient._bound` truncates only
  `result.text` and leaves `structured` alone. `ctx.tool_message` renders `structured`
  whenever it is present, so a large structured result enters context unbounded.
- **AHC-0094 (output-side enforcement)**: the claim guard blocks correctly (tagged AAC-0110).
  But a block returns `Completed(reply=SAFE_REPLY, termination=REFUSED)`, not the `Refused`
  outcome AHC-0094 requires.
- **AHC-0017 on budget/oscillation termination**: these return `Completed` with a
  termination field, so the discriminator is not the type. I tagged AHC-0017 only where
  `Failed`, `Refused` or `Escalated` is actually asserted.
- **AHC-0074 on the retry test**: the dedupe is the agent's own ledger. The key is never
  carried to the MCP server, which is exactly what AHC-0074 says is not enough. I tagged
  AAC-0047 instead.
- **AHC-0039 on the undeclared-side-effect test**: tagged, with a divergence. AHC-0039 says an
  undeclared tool is treated as irreversible; the agent drops it from the surface entirely.
  That is stricter, but it is not what the capability says.
