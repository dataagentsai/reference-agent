## The rules I followed

1. **Tag a statement when the test fully verifies one distinct clause of it.** Where that clause is
   only part of the statement, I list the rest under "Partial coverage". The two cases are
   AHC-0070 and AAC-0043.
2. **Tag on the assertion that carries the test's point, not on setup assertions.** A test whose
   point has no statement stays untagged even if one of its setup assertions happens to touch a
   tagged statement. An example is `test_a_tier_one_escalation_is_not_overridden`. It asserts
   `rule_id == "asked-for-human"`, but its point is that Tier 1 takes precedence over Tier 2, and
   no statement says that. Tagging it would hide the gap.
3. **A component that nothing in `src/` calls cannot discharge a request-path capability.**
   `flow.Throttle`, `flow.retry_after_of`, `resilience.with_retry`, `resilience.Backoff` and
   `resilience.CircuitBreaker` have no callers anywhere in `src/`. The only caller of `flow.*` is
   `loop._dispatch`, and it uses only `gather_bounded`. `llm.GroqClient` relies on the SDK's own
   `max_retries` and turns `RateLimitError` into `ModelUnavailable` along with every other error.
   So the tests of these components pass, but the agent does not have AHC-0021, AHC-0005 or
   AHC-0024. I left them untagged and named the statement that *would* own each one. The
   compensation registry (AHC-0058) is a different case. That capability is a *declaration* the
   harness holds, and the registry is that declaration whether or not anything calls it, so I
   tagged it.

   If you want the opposite rule, where "the statement requires the behaviour" is enough to tag,
   these 13 tests take AHC-0021, AHC-0005, AHC-0024 and B11 as noted in the table.

  refusal of a late close (`esc.resolve`) has no AOAS statement either.

## AOAS findings surfaced by this batch

1. **Vocabulary gap.** Escalation-block statements have no addressable ids: `each_rule_fires`,
   `max_per_conversation`, `queued_ttl`, `on_lapse`, `the_customer_is_told`, and the whole `facts:`
   block. Six untagged tests in this batch verify statements that exist in the AOAS but cannot be
   cited.
2. **Spec vs code conflict.** The AOAS says the customer is told "nothing about when a person will
   arrive". Step 6 (`Capacity`, `QUEUED_REPLY`, `CLOSED_REPLY`) tells them a wait estimate or that
   the desk is closed.
3. **The degraded path claims an action that has no result behind it.** With no escalation store,
   `Agent._escalate` replies "Let me pass you to a colleague who can help with that." when no
   record exists. That is exactly AAC-0110's failure, and it is the defect the escalation module's
   own docstring says was fixed. `test_without_a_store_it_promises_no_reference` checks only
   `ticket_id is None`, so it passes.
4. **Stale gap-asserting test.** `test_a_frustrated_customer_is_never_escalated_today` says it
   should start failing when `repeated-intent` ships. The rule shipped and the test still passes:
   `_facts` stops counting at any `completed` turn or any turn with no intent, so an agentic
   "that is not good enough" loop never counts.
5. **State names diverge.** The AOAS `escalation.state` is `[queued, claimed, resolved, lapsed]`.
   The code is `QUEUED / RESOLVED / EXPIRED`, with no `claimed`.

## Existing tags I believe are wrong (kept, not removed)

- `test_a_transient_failure_succeeds_on_a_later_attempt` → **AAC-0009.** `resilience.with_retry`
  has no caller in `src/`, so this test cannot show that the *system* degrades gracefully on
  provider failure. The live path (`GroqClient`) relies on the SDK's `max_retries` and turns
  `RateLimitError` into `ModelUnavailable` like any other error, which also contradicts AHC-0021.
  The tag credits AAC-0009 to dead code.
- `test_writes_run_one_at_a_time_in_the_order_asked` → **AAC-0046.** AAC-0046 requires fault
  injection ("a node failing mid-graph triggers the defined behaviour"). This test injects no
  failure. It verifies only that writes are serialised. That behaviour has no statement of its
  own, and the closest is AHC-0039's "the class gates dispatch".
