Question 01

What are the different kinds and shapes of AI application?

AI applications come in ten shapes. The industry you're in, which model you use and how big it is don't set the shape. Two questions do:

  1. Who owns control flow? Your code, or the model?
  2. What does the output touch? A person reading it, code consuming it, or the real world?

The shape matters because it decides what the harness around the model has to do. Each shape adds a new way to fail, so each one needs more from the harness.

#ShapeWhat it isControl flowExamples
A1Single-Turn Transform One call in, one answer out. No tools, no retrieval, no memory. The model reworks the text it was given. Your codeClassify, summarise, translate, rewrite
A2Structured Extractor Output is a typed object read by downstream code, not by a person. A schema turns quality failures into type failures. Your codeEntity extraction, form filling, function arguments
A3Grounded Answerer Search a set of documents, then write an answer from what came back. The search step and the writing step fail independently, so each is tested on its own. Your codeRAG, document Q&A, knowledge assistant
A4Conversational Assistant Multi-turn and stateful. Keeps context, memory and user history across turns, but takes no action on its own. Your codeSupport chat, tutoring, guided intake
A5Deterministic Workflow A fixed graph of steps with an LLM call at each node. The handoffs between steps are where new failures appear. Your codeChains, pipelines, batch enrichment
A6Tool-Using Agent The model picks which tools to call, in what order, and when to stop. This is the biggest jump in what you have to test. The modelReAct loops, function-calling agents
A7Multi-Agent System Several agents hand work to each other, under a supervisor or by passing it along. On top of A6, it adds failures in who is allowed to do what, how much each may spend, and how far one agent's mistake can spread. Several modelsSupervisor/worker, specialist handoff
A8Artifact Producer Output is code, SQL, config or a document that will be run or shipped. You can check it by running it, which is the strongest check any shape gets. EitherCode generation, text-to-SQL, infrastructure-as-code
A9Autonomous Operator Runs unattended on a trigger or schedule, with real side effects and nobody watching live. The model, unattendedScheduled agents, auto-remediation, background workers
A10Classifier · Router · Judge The model's output steers other machinery: a routing decision, a guardrail verdict, a quality score. You won't see its errors unless you evaluate the evaluator. Your codeLLM-as-judge, safety classifiers, model routers

Shapes are tags, not a tree

A real system usually has more than one shape. A support agent like the one in this repo is a Conversational Assistant (A4), a Tool-Using Agent (A6) and a Grounded Answerer (A3) all at once. It may also use a Router (A10) to decide when to hand off to a human. Give a system every shape that applies and build the harness for all of them.

Why this matters for the harness

Every shape needs a common core from the harness: input handling, output checks, tracing, cost limits, evaluation. Beyond that core, each shape adds what is new about it. The line that matters most runs between A5 and A6. Up to A5, your code decides what happens next. From A6 on, the model decides, so the harness has to supply the limits your code used to enforce: which tools are allowed, step and cost budgets, stop conditions, and approval before irreversible actions.

In the AI Harness Catalog (AHC), a single-turn transform (A1) needs about 50 harness capabilities, while a multi-agent system (A7) needs about 75. The more control the model has, the more the harness has to do.

Question 02

What layers make up a whole AI application?

A request travels left to right: from the person, through your application and your harness, optionally through an AI gateway, to the model provider that runs the model. The answer comes back the same way. Underneath, a lab trained the model and a cloud runs every box. Each box is a role. One company can fill several roles, which is where most of the confusion comes from.

Four pairs people confuse

PairThe difference
Gateway vs providerA gateway forwards requests. A provider runs the model. LiteLLM or Portkey on its own can't answer a single prompt; it needs a provider behind it. If you remove the gateway, your harness calls the provider directly. That's fine for one app and one provider. Add a gateway when several apps, teams or providers need one set of keys, budgets and logs.
Provider vs labA lab trains the model. A provider serves it. Anthropic is both: the lab that trains Claude and the provider behind the Anthropic API. AWS trains no Claude model, yet Bedrock serves Claude. Meta trains Llama but serves it to almost nobody; you get Llama from Bedrock, Databricks or your own vLLM.
Provider vs cloudAWS the cloud rents you machines (EC2, GPUs). AWS Bedrock is a model provider that happens to run on that cloud. Same company, different layers. Choosing AWS as your cloud doesn't force Bedrock. Your app on AWS can still call the Anthropic API.
Model vs providerOne model, many front doors. The same Claude model is served by the Anthropic API, Bedrock, Vertex and Azure AI Foundry. Features, prices and release timing can differ slightly between them. The model is what thinks; the provider is where you call it.

So when someone says "we use Anthropic", ask which role they mean. It could be the model (Claude), the provider (the Anthropic API) or the framework (the Agent SDK). Each is a separate choice.

How one request flows

  1. A person, or a trigger, sends a request through the application.
  2. The harness (orchestration & context) builds the prompt. It pulls relevant documents through RAG, recalls memory, and lists the tools the model may use.
  3. If there is a gateway, it checks the key and budget, logs the call, and picks a provider.
  4. The provider runs the model, which either answers or asks for a tool. If it asks for a tool, the harness runs the tool, feeds the result back, and loops to step 3.
  5. The answer passes back through output guardrails to the person. Tracing and cost records are written along the way.

Where the harness sits

The model is one box on the far right, and you rent it. Most of the engineering, and every failure from Question 01, lives in the outlined parts: orchestration & context and the cross-cutting band. That is the agent harness, everything around the model that makes it safe and dependable to run. The gateway is drawn dashed because it's optional. When you have one, it enforces some of the harness's controls, such as budgets and key management, at a single shared point.
